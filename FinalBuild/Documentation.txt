Modification Description : what you changed and why its better/funner?
I changed the speed of the paddle to be higher so that the player can feel more in control of the paddle and to make it feel more fair. The previous speed was too slow and you have to be constantly moving with the ball in order for the ball to hit the paddle. I also added a lose and win screen so there is a sense of accomplishment or failure to drive people to play the game. I also added multiple different blocks along with the original block to mix up the game play a little and add more challenges. There are three new blocks: one that requires more hits to break, one that drops a nuke that deals damage when collided with the paddle, and one that makes the paddle bigger.

Structural Changes : what new classes did you add what classes did you modify. Why did you decide to make these changes where you did?
I added a lot of new classes. First of all, I added a level manager class that contains all of the main elements(Paddle, blockmanager, input) of the game and deals with restarting a game. I added this class because I wanted a class that contains all the main elements of the game and calls their restart function when a button is pressed. However, I do feel like I could've not added this class and instead have the Scoremanager or some other class receive the input and change the state of the game and the other classes reset on their own based on the state. Other classes I added was an alternative version of the block class (from which it inherits) that allows for multiple block states based on how many hits. I only added this class because it was the easiest way to allow for a block to receive more hits and update the texture based on those hits. If I had more time, I'd probably changed the way hits and states worked in the original block class so it can allow for blocks to receive more hits. I also added child classes of the monogameblock class that are the new different kinds of blocks that handles the different behaviors of each of the new blocks. Lastly, I added a nuke class that is summoned when the nuke block is destroyed and deals damage to the paddle. Some of the classes I modified where the block manager, I changed the code so that it can handle the behavior of the new blocks when they are destroyed. I also changed the CreateBlockArrayByWidthAndHeight method so that it can randomly choose between the 4 different kinds of blocks. I also changed the paddle class so it has a new texture and state for the large paddle power up as well as methods that handles any behavior surrounding the paddle power up. I also changed the score manager so that it can draw text for game over and win states. 

State Changes : Did you need to refactor any state to accommodate your changes? What did you refactor and why?
I did change a few states to accommodate my changes. I added more states to the blockstate so that it can accommodate the blocks that require more hits to break. I also added a GameState that has a running, gameover, and win state. I added this so that the behavior of different classes only run when the game is running. The state also determines what text is on the screen in the score manager. Lastly, I added a paddle size state to accommodate the new paddle power up.

Maintainability : Did you improve the baseline of the source code to make it more sustainable or did you accrue technical debt?
I definitely accrue technical debt. I had a lot of quick fixes such as the Levelmanager and the BlockAlt classes. If I had more time, I would've refactor the code of these classes into other classes. In the case of the BlockAlt class, I would've changed the way hits and states worked in the original block class so that it can accommodate more different thresholds of hits for different blocks.
